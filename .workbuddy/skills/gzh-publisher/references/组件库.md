# 组件库 v1（13 个）

> **唯一事实源**：改样式只改这里。`排版规范.md` 只讲纪律和索引，不复写片段。
> 2026-10-21 建立。方法论吸收自 `wechat-mp-typeset`（粥左罗 / L先生说 / GQ实验室 的公开拆解）。

## 三条底层依据（比"好看"更硬）

1. **为完读而排版**：2026 微信推荐算法里，完读率权重约为打开率的 1.8 倍。排版目标是让人读完，不是让人夸好看。
2. **手机是扫读**：每段 3–5 行、每 300–500 字一个视觉锚点、每 600–900 字一个视觉补给点（分割线或卡片）。
3. **三色纪律**：正文低饱和黑 + 注释灰 + **一个**品牌色。加粗就是品牌色，是唯一强调通道，滥用即失效。

## 通用规则（写组件前必读）

**允许的标签只有 5 个**：`section` / `span` / `strong` / `br` / `img`，属性只允许 `style`（img 另允许 `src`/`alt`）。
`<p>` `<div>` `<table>` `<ul>` `<h2>` `<a>` 一律不许——前三个会被压平或剥样式，`<a>` 会被转成引用卡片。

**结构三条**：
1. 每个顶层块必须是 `<section>`
2. 文字样式只写在 `<span style>` 上
3. `<strong>` 与 `<span>` **平级**，不能嵌在 span 里（嵌进去样式会被剥）

**多列布局四件套**（缺一件就换行）：
1. 父级 section 加 `font-size:0`（吃掉标签间空白）
2. 子块 `display:inline-block` + `vertical-align:top`
3. 标签之间**零空白**，整段写成一行
4. 宽度百分比合计 ≤ 98%（留 2% 余量）

**间距自带**：每个组件的 `margin` 写在自己 style 上，不能靠 CSS。

## 一、基础组件

### C01 导语（全文第一段，只出现一次）

```html
<section style="margin:0 0 26px;padding-left:14px;border-left:3px solid #1a4d8f;"><span style="font-size:16px;line-height:1.8;color:#555;letter-spacing:0.4px;">导语：一句话说清发生了什么，再说为什么值得看。80–120 字，不要铺垫背景。</span></section>
```

- **用**：开篇倒金字塔。第一句直接给结论，禁止「随着……的发展」。
- **反例**：当摘要用（摘要另有字段）；写三段以上（那就不是导语了）。

### C02 正文段

```html
<section style="margin:0 0 22px;"><span style="font-size:16px;line-height:1.8;color:#333;letter-spacing:0.4px;">正文内容，一段只讲一件事，控制在 90 字以内。</span></section>
```

- **用**：任何叙述。**连续不超过 3 段**，第 4 段前必须换组件（小标题/引用/要点）。
- **反例**：一段塞两个观点；用 `<br>` 手动换行代替分段。

### C03 小标题（两种形态）

带序号（长文首选，扫读时定位最强）：

```html
<section style="margin:38px 0 16px;"><span style="font-size:13px;font-weight:700;color:#1a4d8f;letter-spacing:1px;">01</span><span style="color:#1a4d8f;font-size:18px;font-weight:700;">　▍</span><span style="font-size:18px;font-weight:700;color:#111;line-height:1.5;">事实层：谁做了什么</span></section>
```

不带序号（600 字以内的快讯用）：

```html
<section style="margin:34px 0 16px;"><span style="color:#1a4d8f;font-size:18px;font-weight:700;">▍</span><span style="font-size:18px;font-weight:700;color:#111;line-height:1.5;">小标题文字</span></section>
```

- **用**：把长文切成 3–4 个模块，每模块 500–600 字。
- **反例**：写模糊描述（「一些思考」）——必须提炼观点或疑问（「为什么规则越多越乱？」）；连续两个小标题之间没有正文。

### C04 引用块

```html
<section style="margin:0 0 22px;padding:16px 18px;background:#f6f7f9;border-radius:4px;"><span style="font-size:15px;line-height:1.75;color:#444;">被引用的原话，60 字以内，段末注明说话人和语境。—— 姓名（身份，日期）</span></section>
```

- **用**：原文关键判断、对方回应、专家原话。一篇 0–3 处。
- **反例**：引自己的话；引用超过 60 字（读者会跳过）。

### C05 要点条目

```html
<section style="margin:0 0 14px;padding-left:16px;"><strong style="color:#1a4d8f;">要点标签</strong><span style="font-size:16px;line-height:1.8;color:#333;">　说明文字，用全角空格隔开，一条不超过 70 字。</span></section>
```

- **用**：并列内容（3–6 条）。原文里的「一二三四」排比长段，编译时一律改成这个。
- **反例**：超过 6 条（该拆成两个小标题）；标签超过 8 个字（挤掉说明）。

### C06 判断段（独立成段，全文只有一段）

```html
<section style="margin:26px 0 22px;"><strong style="color:#1a4d8f;">全文最有价值的一句判断放这里，40–70 字，独立成段。</strong><span style="font-size:16px;line-height:1.8;color:#333;">后面可以跟一句解释为什么这么看。</span></section>
```

- **用**：收尾给观点。这是读者唯一会记住的一句。
- **反例**：写成总结（总结是复述，判断是表态）；一段里出现两句加粗。

### C07 来源行（每篇必须有，末块）

```html
<section style="margin:30px 0 0;padding-top:14px;border-top:1px solid #e6e6e6;"><span style="font-size:13px;line-height:1.7;color:#999;">信息来源：XXX（作者，机构，日期）。本文为中文编译，非全文翻译。</span></section>
```

- **用**：文末固定位置。轨道 B 列出全部来源。
- **反例**：放在正文中间；用彩色。

### C08 文内图片（本轮不测）

```html
<section style="margin:0 0 8px;"><img src="https://mmbiz.qpic.cn/..." style="width:100%;display:block;border-radius:4px;" alt="图片说明" /></section>
<section style="margin:0 0 24px;"><span style="display:block;font-size:12px;line-height:1.6;color:#999;text-align:center;">图注：说清这张图在讲什么</span></section>
```

- **用**：每 300–500 字一张（带图文章完读率比纯文字高约 37%）。图片必须先传素材库换 mmbiz 链接。
- **反例**：本地路径（发布后裂图）；无图注；连续两张图。

## 二、卡片组件（本轮新增，待实测）

> 4 个新组件都依赖 `display:inline-block` 多列。微信是否保留这个属性**尚未验证**——见第 5 节实测记录。

### C09 数字三连卡

```html
<section style="margin:2px 0 26px;font-size:0;"><span style="display:inline-block;width:32%;margin-right:1%;vertical-align:top;"><span style="display:block;font-size:26px;font-weight:700;color:#1a4d8f;line-height:1.2;">80%</span><span style="display:block;font-size:12px;color:#999;line-height:1.6;margin-top:6px;">提示词删减比例</span></span><span style="display:inline-block;width:32%;margin-right:1%;vertical-align:top;"><span style="display:block;font-size:26px;font-weight:700;color:#1a4d8f;line-height:1.2;">5</span><span style="display:block;font-size:12px;color:#999;line-height:1.6;margin-top:6px;">模型代次</span></span><span style="display:inline-block;width:32%;vertical-align:top;"><span style="display:block;font-size:26px;font-weight:700;color:#1a4d8f;line-height:1.2;">0</span><span style="display:block;font-size:12px;color:#999;line-height:1.6;margin-top:6px;">可测性能损失</span></span></section>
```

- **用**：三个数字构成一个故事（80% / 5 / 0）。融资的金额-估值-涨幅，评测的三档分数。
- **硬约束**：一篇**最多一处**；三个数字**必须同量纲**（都是百分比，或都是金额）；两格变体用 `48%+1%+48%`。
- **反例**：4 格（每格 24% ≈ 80px，26px 数字必折行）；单位混写（「80%」和「3 倍」放一排）；数值上再加 `<strong>`（会嵌进 span 被剥）。

### C10 时间线

```html
<section style="margin:0 0 24px;padding:2px 0 2px 16px;border-left:2px solid #e6e6e6;"><section style="margin:0 0 16px;"><span style="display:block;font-size:12px;font-weight:700;color:#1a4d8f;line-height:1.5;letter-spacing:0.6px;">10-14</span><span style="display:block;font-size:15px;color:#333;line-height:1.75;margin-top:2px;">事件一句话，45 字以内。</span></section><section style="margin:0;"><span style="display:block;font-size:12px;font-weight:700;color:#1a4d8f;line-height:1.5;letter-spacing:0.6px;">10-21</span><span style="display:block;font-size:15px;color:#333;line-height:1.75;margin-top:2px;">末项 margin 归零，竖线才能收到文字底部。</span></section></section>
```

- **用**：监管事件的演进（哪天发生了什么）、融资历程（上一轮→本轮）、模型版本迭代。
- **硬约束**：3–5 项；日期写成 `10-14` 不要写「10 月 14 日」；**外层**画竖线，内层只放内容；末项 `margin:0`。
- **反例**：每项各自带 `border-left`（段距处会断成几截）；超过 6 项（一屏看不完，改用 C05）。

### C11 参数卡

```html
<section style="margin:0 0 24px;padding:14px 16px 4px;background:#f6f7f9;border-radius:4px;"><section style="margin:0 0 12px;font-size:0;"><span style="display:inline-block;width:32%;vertical-align:top;font-size:13px;color:#999;line-height:1.7;">模型</span><span style="display:inline-block;width:66%;vertical-align:top;font-size:14px;color:#333;line-height:1.7;">Claude Opus 5</span></section><section style="margin:0 0 12px;font-size:0;"><span style="display:inline-block;width:32%;vertical-align:top;font-size:13px;color:#999;line-height:1.7;">上下文</span><span style="display:inline-block;width:66%;vertical-align:top;font-size:14px;color:#333;line-height:1.7;">200K tokens</span></section><section style="margin:0 0 12px;font-size:0;"><span style="display:inline-block;width:32%;vertical-align:top;font-size:13px;color:#999;line-height:1.7;">价格</span><span style="display:inline-block;width:66%;vertical-align:top;font-size:14px;font-weight:700;color:#1a4d8f;line-height:1.7;">输入 $3 / 百万 token</span></section></section>
```

- **用**：发布快讯的「规格 / 可用性 / 价格」；融资的「交易条款」。
- **硬约束**：3–6 行；值列 66% ≈ 220px，14px 一行只放得下 15 个字；**只允许 1 行高亮**（价格或可用性），且与 C09 不要同时高亮。
- **反例**：当表格用（超过 2 列必翻车）；行间加 `border-bottom`（灰底上再加线，脏）。

### C12 榜单行

```html
<section style="margin:0 0 10px;padding:0 0 10px;border-bottom:1px solid #e6e6e6;font-size:0;"><span style="display:inline-block;width:10%;vertical-align:top;font-size:15px;font-weight:700;color:#1a4d8f;line-height:1.7;">1</span><span style="display:inline-block;width:58%;vertical-align:top;font-size:15px;color:#111;line-height:1.7;">模型或方案名</span><span style="display:inline-block;width:30%;vertical-align:top;text-align:right;font-size:15px;font-weight:700;color:#1a4d8f;line-height:1.7;">92.4</span></section>
```

末行改：`border-bottom:0`、`margin:0 0 22px`、`padding:0`。

- **用**：评测榜单、GitHub Trending、多方案对比。
- **硬约束**：**上方必须有口径行**（数据来源 / 评测集 / 截止日期），否则视为违规——这是评测稿最容易翻车的地方；指标列必须右对齐；序号只写 `1` 不写 `No.1`；≤8 行。
- **反例**：指标左对齐（无法纵向比对）；没有口径（读者不知道这个分数能说明什么）。

### C13 分割线（视觉补给点）

```html
<section style="margin:34px 0;text-align:center;"><span style="display:inline-block;width:36px;height:1px;background:#d8d8d8;vertical-align:middle;"></span></section>
```

- **用**：每 600–900 字一处，或者话题转折处。让读者「到一站松一口气」。
- **反例**：连续两段之间就放（把文章切碎）；超过 3 处（节奏反而乱）。

## 三、配色

| 用途 | 色值 |
|---|---|
| 小标题 | `#111` |
| 正文 | `#333`（比纯黑柔和；`#3F3F3F` 也可） |
| 导语 / 次要 | `#555` |
| 注释 / 来源 | `#999` |
| 引用底纹 | `#f6f7f9` |
| 分隔线 | `#e6e6e6` / `#d8d8d8` |
| **强调（唯一）** | `#1a4d8f` |

## 四、5 种推荐拼法（推荐，不是规定）

篇幅三档：**快讯 600–800 / 标准 1000–1600 / 长文 1500–2000**。

| # | 形态 | 组件序列 | 字数 |
|---|---|---|---|
| A | 单点发布 / 开源快讯 | C01 → C11 → C02×2 → C06 → C07（**可以没有小标题**） | 600–800 |
| B | 分析 / 评测 / 基准 | C01 → C02 → [C04] → C03+C02×2 → C09 → C03+C02×2 → [C13] → C03+C05×3 → C06 → C07 | 1000–1600 |
| C | 监管 / 安全事件 | C01 → C10 → C03+C02×2 → C04×2 → C13 → C03+C02 → C05×3 → C06 → C07 | 1000–1400 |
| D | 融资 / 财报 | C01 → C09 → C03+C02×2 → C11 → C10 → C06 → C07 | 800–1200 |
| E | 访谈 / 综述 | C01 → C03+C02×2 → C04×3 → C13 → C03+C02×2 → [C09/C12] → C03+C05×3 → C06 → C07 | 1500–2000 |

带 `[ ]` 的是可选。**这五条是参考，不是必须**——内容需要时可以打乱，只要不违反下面的硬规则。

### 硬规则（违反会明显变丑）

- C09 / C11 / C12 一篇**各最多一处**（多了变报表）
- 任意两处卡片之间**至少隔 1 个 C02 或 C03**，不许卡片连排
- C02 连续不超过 3 段
- 全文加粗 6–10 处；C09 的数值和 C11 的高亮不重复占强调位
- 快讯档允许不写小标题

### 扫读结构公式（长文每节通用）

```
【小标题】一句话概括本节（01/02/03）
核心观点（1 行，加粗）
执行步骤 / 事实（要点条目，每点 1 行）
避坑提醒（1 行，加粗）
```

## 五、实测记录

| 组件 | 状态 | 备注 |

| C01–C07 | ✅ 已验证 | 2026-10-21 v2 样例：`section=20 strong=10 styled=54`，保存重开仍在 |
| C09 数字三连卡 | ⏳ 待测 | 关键指标 `iblock` |

| C11 参数卡 | ⏳ 待测 | 关键指标 `iblock` |
| C12 榜单行 | ⏳ 待测 | 关键指标：指标列右边缘是否对齐 |
| C13 分割线 | ⏳ 待测 | 单行元素，风险最低 |

失败兜底：`inline-block` 被剥 → 三列卡改单列竖排（数值 26px + 标签 12px，`display:block`）；时间线断线 → 每项各带左边框，接受 10px 断口。

## 六、暂不做

- **对比表 / 真表格**：`<table>` 在微信里行为未验证，多列超过 3 列在手机上必挤。需要时用 C05 或 C11 代替。
- **Q/A 块**：目前用 C05（标签写「问：」「答：」）替代，够用。
- **视频 / GIF**：走素材库上传，不进 HTML 组件。
