# 公众号后台 RPA 实测约束

> 全部来自 2026-10-19 在一台 Windows 机器、个人订阅号、真实后台上的实测。
> 这些结论修正过多条早先的错误判断，**以本文为准**。

## 一、环境

### 1. Chrome 必须 `--do-not-de-elevate`

当前 shell 以管理员权限运行，Chrome 检测到自己被提权，会 relaunch 一个去提权的子进程然后自己退出。
表现是**退出码 0、没有任何输出、调试端口不开**，报错只出现在 `--enable-logging=stderr` 里：

```
base\win\elevation_util.cc:132] RunDeElevated: Started process, PID: 63036
```

跟沙箱无关（脱离沙箱一样失败）。加 `--args "--no-sandbox,--do-not-de-elevate"` 立刻正常。

### 2. 一次调用 = 一个自包含 batch

agent-browser 的守护进程活不过一次进程调用。跨调用依赖页面状态必然拿到 `No active sessions` 或 `about:blank`。

正确写法：把 `open + wait + 全部动作` 放进同一个 batch，stdin 喂 **JSON 数组**：

```json
[["open","https://..."],["wait","7000"],["eval","..."]]
```

### 3. 不能管道捕获输出

浏览器守护进程会继承并长期占用 stdout 管道，父进程永远等不到 EOF。`capture_output=True`、`| head` 都会永久挂起。
统一 `stdout=临时文件`，子进程退出后读文件。

### 4. 视口必须够大

默认 1080×498。封面弹窗、「编辑封面」裁剪层、发表弹窗的底部按钮都会被切到视口外，
`click` 计算出的坐标落在视口之外，**点了但什么都没发生**——最难查的一个坑。

所有流程开头都 `["set","viewport","1440","1200"]`。

### 5. `offsetParent` 对 fixed 弹层是 null

用它判断"元素可见"会把弹窗里的按钮全判成不可见。用 `getBoundingClientRect().width>2`。

## 二、编辑器字段地图

| 字段 | 怎么填 |
|---|---|
| 标题 | `.ProseMirror`[0]：focus → `execCommand('selectAll')` → `insertText` |
| 正文 | `.ProseMirror` 中**高度 >120 可见**的那个（不要硬编码 `[1]`）；真实点击后整篇一次 `insertHTML` |
| 摘要 | `textarea#js_description`：赋 value + dispatch `input`/`change`。**必须写在正文之后** |
| 作者 | `input#author` |
| 原文链接 | ❌ 填不进去（见下） |
| 封面 | 见「三、封面」 |

**反直觉的坑（每条都实测过）**：

1. 标题**不能**用 `textarea#title`——那是隐藏字段，`fill` 会把标题文字敲进正文。
2. 正文**不能**直接改 `innerHTML`——ProseMirror 不认，保存时会丢。必须走 `execCommand`。
3. **段落标签必须是 `<section>`，不能用 `<p>`。**
   `<p>` 会被编辑器合并压平成一块，`<strong>` 和内联样式全丢——2026-10-20 那篇「挤成一坨」就是这个原因。
   改用 `<section>` + `<span style>` 后，整篇一次插入即可保真（实测 19 段 → `section=20 strong=10 styled=54`，保存重开仍在）。
4. **`b.click()`（JS 点击）不会移动焦点**，`execCommand` 会打在空气上，表现为 `BODY_BLOCKS` 还是旧值、`BODY_LEN=10`。
   必须用 agent-browser 的 `click` 命令发**真实鼠标事件**（先给正文区打 id 再 click）。
5. **不要拆成多次 `insertHTML`**：后面的段落会被吞进前一段的 `<span>` 里（嵌套变形）。
6. 新建流程（`isNew=1&type=10`）打开后正文区可能还没初始化，`[1]` 是一个 10 字的空编辑器；
   写完标题要等 1.5s，并且用「高度最大」来定位正文区。
7. 脚本在保存前会核对块数与加粗数，不一致就 `SKIP-SAVE-BAD-BODY` 并**放弃保存**——**不要绕过这个闸门**。
8. **组件内部允许嵌套 `<section>`**（时间线、参数卡都必须嵌套），但统计必须用**深度计数**：
   旧实现 `low.find("</section>", …)` 取最近的闭合标签，会把 1 块算成 2 块，
   自检基数虚高、闸门误判。2026-10-21 已改为标签栈计深度。
9. **正文白名单只有 5 个标签**（section/span/strong/br/img），由 `scan_body()` 在**开浏览器之前**校验；
   `<p>` `<table>` `<div>` `<ul>` `<h2>` `<a>`、`on*` 事件属性、非 `style` 属性都会被拦下或剥掉。
   写稿时随手验：`python scripts/gzh_draft.py --manifest xx.json --check-only`。
10. **保存闸门是四项**：`section / strong / styled / inline-block` 元素数。
    其中 `inline-block` 是唯一能自动发现「多列卡片塌成单列」的指标，专为新组件设的。
11. **封面宽高比**：头条要 2.35:1（900×383），容差 ±8%。直接取 `og:image` 常是 1.9:1（1200×630），
    偏差 18.9%，会被裁掉核心信息 —— 出稿前用
    `~/.workbuddy/skills/wechat-mp-typeset/scripts/cover_check.py 封面.png` 校验并裁剪。



### 原文链接为什么填不进去

`input#source_url` 默认不存在，要先点 `#js_article_url_area .js_article_url_click` 才展开，
且展开后的 input **可能没有 id**，只能按 placeholder 定位。

更关键的是启用开关 `input[name=source_url_checked]` **无法程序化勾选**
（点 label / 点 input / 赋 value / `fill` 四种方式都试过，`checked` 始终 false），
所以输入框一直是禁用态，写入不生效。

**替代方案**：来源署名写进正文（`信息来源：AI前线（InfoQ）`）。

## 三、封面：有菜单，不是文件框

点 `.js_cover_btn_area` 弹出的是**下拉菜单** `ul.pop-opr__list`，四个选项：

1. 从正文选择
2. **从图片库选择**
3. 微信扫码上传
4. **一键生成封面**

早期"点它没有任何网络请求、DOM 也无 file input，所以没有程序化入口"的结论是**错的**——
菜单是预先存在、靠切换 display 显示的，所以既不新增节点也不发请求。

### 可用通路（已端到端跑通）

```
素材库 filepage 页 upload input[type=file]
  → 编辑器点封面区（.js_cover_btn_area）
  → 菜单选「从图片库选择」
  → 在 div.weui-desktop-img-picker__item 里按文件名前缀选中
  → 按钮变「下一步」→ 点
  → 「编辑封面」裁剪层 → 点「确认」（注意：不是「完成」）
```

**注意**：
- 素材库上传要唯一文件名，否则库里同名图分不清。`gzh_draft.py` 用内容哈希命名 `cvr<10位>`。
- 编辑器的 `input[type=file]` 是**正文插图**用的，往它上传会把图插进正文，封面仍为空。
- 封面**已设置时**点封面区不弹菜单（走的是另一套预览逻辑），此时封面流程整段跳过即可。

### 可靠的成功信号

```js
getComputedStyle(document.querySelector('.js_cover_preview_new')).backgroundImage
// 含 mmbiz.qpic.cn → 已设置
```

❌ 不要用「拖拽或选择封面」这段文字判断：它始终留在 DOM 里（隐藏），永远为真。

## 四、发表：三层，最后一层必须人扫

```
点编辑器「发表」
  → 弹窗：群发通知(默认开) / 分组通知 / 定时发表 → 点「发表」
  → 二次确认：「已开启群发通知…」或「未开启群发通知…」→ 点「继续发表」
  → 微信验证：扫码后，请联系管理员进行验证
```

**关键实测**：`群发通知` 开关可以程序化关掉（点 `.mass_send__notify label.weui-desktop-switch`，
状态可用「分组通知那一行是否消失」判断），**但关掉之后点「继续发表」照样弹二维码**。

也就是说：**扫码绑定的是「发表」这个动作，不是「群发」。绕不过去。** 这一点已经验过，不要重复尝试。

### 三条路径全部试过，都要扫码（2026-10-19）

| 尝试 | 设置 | 点「继续发表」之后 |
|---|---|---|
| 正常群发 | 群发通知开 | **弹二维码** |
| 只发布不群发 | 群发通知关（二次确认文案变成「未开启群发通知」） | **弹二维码** |
| 定时发表 | 定时开（开关可程序化打开，时间框 `input.weui-desktop-form__input` 可写入，如 23:59） | **弹二维码** |

结论：**发表动作本身触发管理员扫码验证，与「是否群发」「是否定时」无关。**
合规范围内没有绕过口子。

剩下能想到的都是违规路径（伪造验证票据、逆向内部接口、改客户端），代价是封号，不建议也不做。

**唯一有价值的变化**：定时发表的扫码发生在**设置时刻**，不是发送时刻。
所以人的参与时间可以自由安排（例如晚上扫一次、定好次日 08:00 发），但**每篇仍需一次扫码**。

### 「一次验证能否连发多篇」也否证（2026-10-19 16:40）

猜想：扫码后是否有一个信任窗口，短时间内再发不用再扫。

实测：扫码成功发出第 1 篇（`100000047` 从草稿箱消失、已发表）→ 立刻发第 2 篇（`100000042`）
→ 走到「继续发表」后**仍然弹出二维码**。

结论：**没有信任窗口，每篇都要扫一次。** 至此四条路（群发 / 不群发 / 定时 / 连发复用）全部否证。

### 选择器坑

页面上有**两个同名「发表」按钮**（编辑器一个、弹窗一个）。用 nth / last 会点错，
必须用「祖先里有没有 `dialog` 类」区分：

```js
var d = bs.filter(function(b){
  var p=b; for(var i=0;i<9&&p;i++){ if(String(p.className||'').indexOf('dialog')>=0) return true; p=p.parentElement; }
  return false;
});
```

### 发表弹窗的开关状态

- `label.weui-desktop-switch` 的 class 会长期停在 `weui-desktop-switch_loading`，**不能用来判断开/关**。
- 可靠判断：**「分组通知」这一行是否存在**（开启时显示，关闭时消失）。

## 五、草稿箱与删除

- 列表 URL：`/cgi-bin/appmsg?begin=0&count=10&type=77&action=list_card&token=XXX&lang=zh_CN`
  （`type=77`；**不能带** `t=media/appmsg_list`，否则渲染空列表）
- 卡片选择器：`div.weui-desktop-card[data-appid="<appmsgid>"]` —— **appmsgid 就在 `data-appid` 上**。
  卡片里的链接全是 `javascript:void(0)`，靠 href 找不到目标。
- 删除是**无文字的垃圾桶图标**：`.weui-desktop-publish__opr a` 的第 1 个（第 2 编辑、第 3 发表），
  且**必须先 hover 卡片**才出现。
- 确认框是**浮层**不是 dialog：「确定删除？… 删除 / 取消」，点最后一个文字为「删除」的可见元素。
- **素材库图片删不掉**：悬停只有重命名输入框；「管理」是管分组，不是批量删除。

## 六、合集（公众号的「分类栏」）

后台没有「分类」功能，对应的是**合集**（侧栏「合集」，`/cgi-bin/appmsgalbummgr?action=list`）。

### 硬规则

| 规则 | 说明 |
|---|---|
| **每篇最多 1 个合集** | 编辑器面板上明写「每篇文章最多添加1个合集」。官方功能说明里说的「5 个标签」不适用于编辑器，**以编辑器为准** |
| 名称修改间隔 24 小时 | 建之前想好名字 |
| 合集必须含已发表内容 | 空合集点「发布」会弹「保存失败」——但**合集其实建成了**，这个 toast 不可信 |
| 「添加已有内容」只能选已发表文章 | 草稿必须先发表 |

### 两条路，都已验证

**A. 发布前挂（推荐，可全自动）** —— 在编辑器里设置，六步缺一不可：

```js
// 1 勾选（这个复选框是活的）
document.querySelector('#js_article_tags_area input.js_article_tags').click()
// 2 点「未添加」打开面板
document.querySelector('#js_article_tags_area .js_article_tags_label').click()
// 3 点开下拉框（不点开不列选项，面板默认是空的）
document.querySelector('input[placeholder="请选择合集"]').click()
// 4 在下拉项里按文本点中目标合集
// 5 点「确认」
// 6 照常「保存为草稿」
```

实测信号：确认后编辑器右侧显示 `合集 <名称>`；**重新加载页面后仍在**（已持久化）。

**B. 发布后补挂** —— 合集管理页 → 编辑 → 添加已有内容 → 勾选文章 → 确定 → 发布：

```js
// 勾选框是自定义样式，真正的控件是隐藏的 input，点可见图标 i[class*=icon-checkbox] 即可
[...document.querySelectorAll('i[class*=icon-checkbox]')]
  .filter(e => e.getBoundingClientRect().top > 150)[0].click()
```

实测：选完显示「已选择 1/1000」，确定后合集内容数从 0 变 1，发布后生效。

### 坑

- 勾选框**不是**原生可见的 `input[type=checkbox]`：`.weui-desktop-form__checkbox` 在屏幕外
  （`x=-139579`），直接按「取第一个」点会点到**全选框**（计数仍为 0）。要点那个可见的
  `i.weui-desktop-icon-checkbox`。
- 编辑器里的合集复选框 `input.js_article_tags` **可以**程序化勾选——
  **不要和「原文链接」的 `source_url_checked` 混为一谈，那个是真的勾不动。**

## 七、登录态

- cookie 有效期约 **4 天**（`slave_sid` / `data_ticket` 等），`wxuin` / `xid` 约 1 年。
- 但会**提前失效**，原因不是过期：
  - **单点互踢**：用户在自己浏览器登录后台，这边立刻失效（有明确时间点佐证）。
  - **高频操作 / 触发安全验证后**：会话可能被服务端作废。
- 因此：**任何自动流程都必须把「停在登录页」当一等错误**，记录并通知人重扫，绝不可挂着重试。

## 八、后台入口变动

「设置与开发 → 开发接口管理」已于 **2025-12-01 迁至微信开发者平台**，公众号后台不再有那一页。
个人订阅号没有草稿箱 / 素材接口权限（`draft/add` → 48001），`freepublish` 仅对企业认证开放。
**所以 RPA 是唯一通路**，与实现难度无关。
