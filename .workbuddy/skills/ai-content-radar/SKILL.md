# AI 选题雷达

## 用途

把「今天 AI 圈有什么值得写」固定成一条可重复执行的流水线：**扫源 → 筛选聚合 → 出一期雷达 HTML**。

产出的雷达是**选题池**，供人挑题。后续的核原创标、写成稿是另一条链路，**不在本技能范围内** —— 不要在本技能里顺手把稿写了。

判断标准不来自本技能，来自工作区的两份文件，**每期都要先读**：

- `来源清单.md` —— 跟哪些源、各源入口与采集层级、已验证的技术事实、待办
- `写作规则.md` —— 两条轨道（原文转载 / 原创聚合）与转载合规前提

**定位工作区根目录**：本技能位于 `<工作区根>/.workbuddy/skills/ai-content-radar/`，向上三级即工作区根。若该目录下没有 `来源清单.md`，先问用户产线在哪，**不要臆造源清单**。

## 硬规则（每期都适用，不可妥协）

1. **不核验、也不冒充核验。** 雷达阶段**不打开公众号文章页**去判 `copyright_stat`（逐篇抓取会触发风控）。因此本页**禁止使用「可转·注明来源」标签**——那个结论必须建立在核验之上，属成稿链路。标签默认「待核验」，其余见 `references/选题判断标准.md` 第六节。
2. **不编造。** 标题、链接、数字、时间必须来自实际抓到的内容。抓不到就不写。链接只取抓取时返回的真实 URL（feed 的 link 字段、页面上的 href），**不做任何拼接与猜测**。
3. **宁缺勿假。** 某个源抓取失败，就在交付说明里如实报告"某源本期未采到 + 原因"，不要用旧数据补齐、不要拿相似标题顶替。
4. **批量用 RSS，详情才单篇抓。** 发现阶段走 RSS / 列表页（零风控）；只在候选定下来后，才对**被选中的少数条目**单篇抓详情。绝不要"把几十条候选全部抓一遍正文"。
5. **聚合源的文字不能当素材。** AIHOT 条目的 `desc`（中文摘要）与 `aihot.reason`（推荐理由）是 AIHOT 的原创文字，写进雷达卡片时必须自己重新组织；它们也**不参与**「转载可行性」判断（不是公众号文章，没有 `copyright_stat`）。`aihot.score` 只作参考，不替代 `选题判断标准.md` 的评分。
6. **只写该写的文件。** 只动 `雷达/*.html` 和 `来源清单.md` 的三处：更新记录、待办勾选、以及**纠正已被本期实测推翻的事实**（纠正时必须带上实测日期，不做无关改写）。其他文件一律不动。

## 流程

### 第 0 步 · 准备

1. 读 `来源清单.md` 与 `写作规则.md`。
2. 取当天日期，**用 shell 取，不要自己算**：`date +%F`。
3. 定**期号**：看 `雷达/` 下已有文件名，期号 = 最大期号 + 1；目录不存在则新建，本期为第 1 期。
4. 读**上一期雷达**（期号最大的那个），提取其选题标题，作为本期去重依据。
5. 读 `references/来源与入口.md`。**该文件的入口表是实测结论，优先于 `来源清单.md` 里的早期描述**（清单里"量子位 / 新智元需靠浏览器抓官网"已被实测推翻，两者都有官方 RSS）。

### 第 1 步 · 采集

先跑脚本，一次把 RSS 源拿全：

```bash
python "<技能目录>/scripts/fetch_feeds.py" \
  --hours 36 \
  --out "<工作区根>/.cache/radar-<日期>-raw.json"
```

输出 JSON 里每条候选含 `source / title / link / published / age_hours / desc / title_key / same_title_in`。
stderr 会打一份**采集报告**，逐个源标 `[OK]` 或 `[FAIL]`，先看这份报告再往下走。

源清单在 `<技能目录>/sources.json`（加源改那里，不改代码）；脚本抓 `channel=rss` / `channel=aihot` / `channel=hn` 三类条目，`channel=web` / `manual` 不走脚本。AIHOT 条目的候选里会多一个 `aihot` 字段（`score` / `reason` / `category` / `source_name` / `item_url`），**它的 `desc` 是 AIHOT 写的中文摘要，只能当线索，不能进稿**——见硬规则 6。

**`lang` 字段决定后续怎么做（2026-10-19 起）：** 每条候选带 `lang`（默认 `zh`）。
- `lang=zh` → 中文源，走改写/聚合（不要"编译"，本来就是中文）
- `lang=en` → 英文源，走**编译**：`gzh_source.py` 抓正文+封面 → 用自己的话写中文 → 正文末尾标注「信息来源：<原文标题>，<作者>，<日期>」并注明「非全文翻译」
- **不要全文翻译**：翻译权是著作权人专有权利，标注来源不等于获授权。编译（重组要点、数据、背景）风险显著更低。
- `channel=hn` 的条目按**投票数**排序而非时间，`desc` 前缀带 `[HN N 分]`；link 是外部原文地址可直接抓，回落到 `news.ycombinator.com` 的讨论页**不要选**（没有正文）。

其余入口按 `references/来源与入口.md` 执行，两点特别注意：

- **GitHub Trending**：脚本直连会被环境代理拦（502），必须走网页抓取通道读 `https://github.com/trending?since=daily`。
- **公众号专属号**（AI产品阿颖 / AIGC开放社区 / 机器之心）：无官网无 RSS。**必应 `site:` 检索已实测失效，不要在这上面花轮次。** 主通道是用户在微信里转发链接；拿不到就如实列入"本期未采到"。

候选定下来后，对**被选中的少数条目**单篇抓正文——写要点必须靠它（RSS 只给标题，InfoQ 连摘要都没有）：

```bash
python "<技能目录>/scripts/fetch_article.py" --url "<文章链接>" --url "<文章链接>"
```

正文会落盘缓存，同一篇不会重复抓。**只对被选中的条目调用，不要拿它批量刷候选**（正文抓取有风控成本，见 `references/来源与入口.md` 第二节）。

### 第 1.5 步 · 聚簇（脚本）

候选定下来后，先机器合并一次，再进人工筛选：

```bash
python "<技能目录>/scripts/cluster_events.py" \
  --in "<工作区根>/.cache/radar-<日期>-raw.json" \
  --out "<工作区根>/.cache/radar-<日期>-events.json"
```

- 输出里每条事件带 `member_count` / `sources` / `aihot_score` / `review`；`review=true` 的是机器合并出来的簇，**必须人工过目再定稿**。
- 它只擅长「同一篇通稿被多家转发」（标题字面高度相似，实测相似度 0.97 那种）；
  **不同措辞报道同一件事，它认不出来**（相似度通常掉到 0.3 以下）。所以第 2 步的
  「不同措辞的同一事件要自己认」仍然成立，脚本只替你干掉最机械的那部分。
- 合并偏保守是故意的：**误合并会把两件事说成一件，属事实错误；漏合并只是多一张卡片。**
  想更激进就调低 `--threshold`，但先看 `review` 簇对不对。

### 第 2 步 · 筛选与聚合

**这是决定雷达质量的一步**。按 `references/选题判断标准.md` 执行，要点：

1. **主题过滤**：把 AI 拿掉还成立的内容一律剔掉（电商促销、招生、营销方法论）。
2. **事件聚合**：同一事件被多家报道 → **合并成一张卡片**，标题取信息量最大的那家，其余作并列链接。脚本的 `same_title_in` 只抓完全同名，不同措辞的同一事件要自己认。
3. **优先级打分**：★★★ / ★★ / ★，一期 ★★★ 控制在 5 条以内。
4. **栏目归位**：今日焦点（3–6）/ 行业与资本 / 技术与开源 / 待观察（2–4），总量 16–22 条。
5. **标签初判**：默认「待核验」；专业媒体原创号用「需授权（预期）」；GitHub 等素材用「仅素材」。
6. **跨期去重**：与上期重复的剔除；有实质进展的保留，并在要点首条注明「上期已报，本期进展：……」。

### 第 3 步 · 输出

1. 以 `assets/radar-template.html` 为骨架替换占位符，按文件内注释的卡片范例填充。**CSS 原样保留**——这套样式是已交付过的成品样式。
2. 编号全期连续、两位数补零，跨栏目不重新计数。
3. 写到 `雷达/<YYYY-MM-DD>.html`（同日多期加 `-2` 后缀）。
3.5 **必须跑加工器**，给每条加「一键发送」按钮并清除残留的建议角度：
   ```bash
   python "<工作区根>/scripts/radar_enrich.py" "<工作区根>/雷达/<本期文件>.html"
   ```
   输出里「残留建议角度」必须是 **0**。按钮依赖 `scripts/radar_server.py`（默认 8899 端口），
   需要「点一下就出稿」时先把它跑起来。
   **不要写「建议角度」**——稿子由 agent 写，那是内部思路，不该出现在交付物上。
4. 回写 `来源清单.md`，只做三件事：
   - 「更新记录」追加一行：`- <日期> 第 N 期雷达（共 M 条）`；
   - 「待办」里本期已完成的项**勾掉并在同一行补一句结论**（只勾不增）；
   - 若本期实测推翻了本文件里的既有事实（入口失效、判断过期），就地改正并**标上实测日期**。
   除这三处外不改动其他内容。
5. 若本期发现了新的入口、新的失效做法、新的风控规律，**同步更新 `references/来源与入口.md`**，让下一期不必重新踩坑。

### 第 3.5 步 · 入库与刷新看板（每期必做）

```bash
python "<技能目录>/scripts/update_pool.py" \
  --pool "<工作区根>/雷达/pool.jsonl" --date <YYYY-MM-DD> --issue <N> \
  --events "<工作区根>/.cache/radar-<日期>-events.json" \
  --filter-html "<工作区根>/雷达/<日期>.html"

python "<技能目录>/scripts/build_dashboard.py" \
  --pool "<工作区根>/雷达/pool.jsonl" \
  --radar-dir "<工作区根>/雷达" \
  --out "<工作区根>/雷达/index.html"
```

- `pool.jsonl` 是**长期选题池，只增不删**，一行一个事件。它是跨期记忆：单期雷达只回答「今天有什么」，池子才能回答「哪件事被连报三天」和「哪条放了三天没人写」。
- `--filter-html` **必须给**：候选池有几十条，雷达只收录十几二十条，不给过滤器会把落选的全灌进池子。
- `雷达/index.html` 是**固定地址的持续看板**，每次跑完重绘，收藏一个就够。别把它当成某一期的替代品，它只做汇总，当期详情仍看 `<日期>.html`。

### 第 4 步 · 交付

1. 打开成品给用户看（HTML 走结果展示通道）。
2. 回复里给一段**导读**：今天几条主线是什么、哪 2–3 条最值得写、为什么。
3. **如实报告本期哪些源没采到、原因是什么。**
4. 结尾问用户挑题（沿用页脚用法：回复编号 + 指定轨道）。

## 交付前自查

- [ ] 每张卡片的链接都来自实际抓取，没有拼凑出的 URL
- [ ] 全页没有出现「可转·注明来源」标签
- [ ] 没有与上期重复的选题（或已明确标注「本期进展」）
- [ ] 页头的期号 / 日期 / 条数 / 来源列表与实际内容一致
- [ ] 抓取失败的源已在回复里如实说明
- [ ] 同一事件没有被拆成多张卡片
- [ ] `review=true` 的合并簇已逐个人工看过，没有把两件事并成一张卡

## 资源

| 文件 | 用途 |
|---|---|
| `references/来源与入口.md` | 各源实测入口表、通道性质差异、失效做法、失败处理。**每期采集前必读。** |
| `references/选题判断标准.md` | 主题范围、进雷达标准、事件聚合、优先级、栏目归位、标签规则、卡片写法。 |
| `assets/radar-template.html` | 雷达 HTML 骨架（含 CSS 与卡片范例注释）。 |
| `scripts/fetch_feeds.py` | 多源 RSS 抓取与归一化，输出 JSON + 采集报告。 |
| `scripts/fetch_article.py` | 单篇正文抽取（先试 WordPress 接口，再退回抓 HTML），带落盘缓存。 |
| `scripts/cluster_events.py` | 事件聚簇：把同一事件的多篇报道合并成一个事件，输出 `events.json`（含 `review` 标记）。纯本地，不调模型。 |
| `scripts/update_pool.py` | 把本期收录的条目并进 `<工作区根>/雷达/pool.jsonl`（只增不删），累积成跨期选题池。 |
| `scripts/build_dashboard.py` | 读池子重绘 `<工作区根>/雷达/index.html`（持续看板：多日复现的事件 / 近期新增 / 历史各期）。 |
| `sources.json` | 源清单（含失效源的登记与原因、按源的时区校正、`lang` 语种标记）。 |
| `<工作区根>/scripts/radar_enrich.py` | 雷达页加工器：删建议角度、给每条注入「一键发送」按钮。**每期出完必跑。** |
| `<工作区根>/scripts/radar_server.py` | 一键发送的本地后端（127.0.0.1:8899），把点击写进 `.cache/send-queue.jsonl`。 |
