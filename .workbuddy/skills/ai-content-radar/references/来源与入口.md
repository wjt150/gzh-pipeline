> `来源清单.md` 写在建线当天，其中「量子位/新智元 需靠浏览器抓官网」这条已被实测推翻。
> 本文件的"实测日期"若已过去超过一个月，重新验一遍再信。

**最近实测：2026-10-19**（AIHOT 接入；量子位代理 502、新智元非法字节两处故障已修）

## 二、三条通道的性质差异（决定了怎么用）

1. **RSS 通道**：批量、零风控、字段规整。缺点是只给标题 + 一句话摘要，够用来**发现**，不够用来**写要点**。
2. **网页抓取通道**：字段更全（新智元首页给时间戳 + 原始出处 + 热度值；量子位列表给相对时间 + 编辑摘要），但每条都要一次请求。
3. **公众号文章通道**：能拿到完整正文，但**有风控**——连续快速访问会触发"环境异常"验证页（已实测过一次）。
4. **聚合通道（AIHOT）**：二手精选，一次请求拿回一批**已做中文摘要、已打分、部分已跨信源合并**的条目，字段规整（JSON）。它的价值是补一手源没覆盖到的事件；它的代价是你拿的是**别人的编辑口味**，且摘要/推荐理由是 AIHOT 的原创文字。

> **AIHOT 的三条红线**
> 1. 它的 `summary` / `reason` **只能当选题线索**，不得改写后当成自己的稿子素材；引用一律回 `links.original`。
> 2. 不要用它替代一手源做「转载可行性」判断——它不是公众号文章，没有 `copyright_stat`。
> 3. 只作补漏，不做主源。全量依赖它，选题会和所有盯 X 热帖的号撞车。
>
> 实测（2026-10-19）：AIHOT 15 条精选与量子位/新智元/InfoQ 三条 RSS 的 45 条候选，标题相似度全部低于 0.35，**没有一条撞车**——说明两者覆盖的是不同切片（它偏 X/官方博客/海外媒体，RSS 偏国内媒体）。但标题不撞不等于事件不撞，聚簇那一步仍要人工认。
>
> 另：AIHOT 信源里**包含少量公众号**（实测出现「公众号：数字生命卡兹克」），但它不覆盖你点名的 AI产品阿颖 / 机器之心，别指望它补这个缺口。
> 还实测到它自己的聚簇并不完美：同一件事（卡兹克实测 RTX Spark 笔记本）以「公众号」和「X」两个信源各出了一条。

由此得出的采集策略（别绕过它）：

> **RSS 发现 → 筛选定候选 → 只对候选单篇抓详情。**
> 绝不要"把 35 条候选全部抓一遍正文"，那是最容易触发风控的做法。

## 三、正文抓取通道（只在候选定下后用）

RSS 只给标题（InfoQ 连摘要都没有），「要点 2–3 条」必须读正文。两条通道，按站点选：

| 站点 | 通道 | 实测结果 |
|---|---|---|
| 量子位 | `https://www.qbitai.com/wp-json/wp/v2/posts/<id>?_embed=1` | ✅ 4441 字。**文章页本身会 403**（防护比 RSS 严得多），别硬抓 |
| 新智元 | `https://aiera.com.cn/wp-json/wp/v2/posts/<id>?_embed=1` | ✅ 3395 字。文章页是 JS 动态加载，直接抓 HTML 只拿到「正在取这篇稿子…」共 105 字 |
| InfoQ | 直接抓文章页 HTML | ✅ 9637 字 |

- 量子位与新智元都是 WordPress，`<id>` 就是 permalink 里的数字段（量子位形如 `/2026/10/503446.html`，新智元形如 `/.../admin/118824/<slug>/`）。
- `scripts/fetch_article.py` 已内置这套逻辑：先试 WP 接口，不适用或正文太短再退回抓 HTML，并把正文落盘缓存。
- **纪律**：只对已选中的少数条目单篇调用，不要拿它批量刷候选；同一篇不重复抓（脚本按 URL 哈希缓存）。

## 四、明确失效的做法（别浪费时间）

| 做法 | 状态 | 说明 |
|---|---|---|
| 必应 `site:mp.weixin.qq.com <号名>` | ❌ 失效 | `site:` 操作符在当前搜索通道里不生效，返回结果基本不是公众号页面。**不要为它花轮次。** |
| `rsshub.app/<任意源>` | ❌ 不可用 | 502 Bad Gateway（环境代理拦截） |
| `jiqizhixin.com/rss` | ❌ 不是 feed | 返回的是"机器之心·数据服务"网页 |
| 脚本直连 github.com | ❌ 被拦 | 改用网页抓取通道 |
| 抓量子位文章页 HTML | ❌ 403 | 它的文章页会拦，但 WP 接口放行（见第三节） |
| 抓新智元文章页 HTML | ❌ 空 | JS 动态加载，只有占位符；走 WP 接口（见第三节） |
| `aihot.virxact.com/api/public/*` | ❌ 2026-10-31 停用 | 旧域名与旧接口同时下线，全部换 `aihot.news/api/v1`（字段一一对应） |

### 量子位 RSS 滞后（2026-10-19 实测，重要）

- `qbitai.com/feed` 最新条目为 **10-17 20:21（+08）**，而官网首页同期存在「14 小时前」的条目 → **RSS 比官网落后约 1 天**。
- 同一小时内两次运行，feed 先返回 10-16 那批、后返回 10-17 那批，说明它的 feed 还有 CDN 缓存抖动。
- **后果**：`--hours 24` 窗口下量子位可能一条都选不进来，且不会报错——静默漏采，比抓失败更危险。
- **处理**：日更场景不要把量子位 RSS 当新鲜度依据。要它当天的内容，走 `channel=web` 的官网列表（`https://www.qbitai.com/`，带「N 小时前」相对时间）；或在雷达里对它单独放宽窗口并标注「可能滞后」。

## 五、单源失败怎么办

1. **先如实记录**，不要用旧数据或相似标题顶替。
2. 单源失败**不阻塞**其他源——脚本会把它报成 `[FAIL]`，继续抓剩下的。
3. 常见原因与处理：
   - `HTTP Error 403`（实测量子位）→ **是 UA 判定，不是限流**：它会把完整浏览器 UA 判为爬虫，
     但对极简 `Mozilla/5.0` 放行。脚本已内置 UA 轮换，正常情况会自动绕过；
     若仍失败，本期改用该源的网页列表页（见 sources.json 里 `channel=web` 的同名条目）。
   - `502 Bad Gateway` → 环境代理拦截，该通道不通，换通道。
     **例外（2026-10-19 实测）**：量子位是被本机代理拦的（`Tunnel connection failed`），直连正常 200。
     处理方式是在 `sources.json` 该源上置 `"bypass_proxy": true`，脚本会绕开 `http_proxy` 直连，
     不要误判成"量子位封了我们"。
   - `ParseError: not well-formed`（2026-10-19 实测新智元）→ feed 里混入了非法字节或截断的多字节字符。
     脚本已内置兜底：UTF-8 有损解码 + 剔除 XML 非法控制字符后重解析，代价只是个别字出现替换符。
     若仍失败，说明坏得更彻底，本期如实报 `[FAIL]`。
   - AIHOT 返回 `429` → 按响应头 `Retry-After` 等待（脚本已实现）；不要连发。
   - 拿到了内容但解析不出条目 → 该地址可能不是 feed（返回了网页），记进本文件的失效表。
4. 交付时必须告诉用户：**本期哪个源没采到、原因是什么**。

## 六、公众号文章（只在需要时读）

- 文章页字段里 `copyright_stat=0` 表示未声明原创；页面上有"原创"徽标元素。
- **雷达阶段不读公众号文章页**，因此雷达里不会出现"可转"结论（见 `选题判断标准.md` 的标签规则）。
- 读到正文时：逐篇、低频、读完立即落盘到 `<工作区根>/.cache/`，不重复抓同一篇。
