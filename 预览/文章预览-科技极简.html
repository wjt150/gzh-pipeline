Anthropic 删掉了 80% 的系统提示词，模型反而更强

到了早上. · AI 工程实践 · 2026-10-21

Anthropic 做了一件反直觉的事：把 Claude Code 的系统提示词删掉了 80% 以上，换成 Opus 5 和 Fable 5 之后，内部编码评测没有任何可测量的性能损失。
这不是一次提示词调优，而是一次范式切换。删掉的不是废话，是他们过去赖以工作的整套世界观。
过去在「给 Claude 立规矩」，现在改成「让 Claude 用判断力」。—— Claude 官方博客
▍为什么删？因为规则会打架
他们翻自己的使用记录，发现同一个请求里同时躺着「文档该写就写」和「绝对不要写注释」——系统提示、技能、用户请求互相冲突。
模型最终能猜对意图，但每次都要额外花力气去调和这些矛盾。规则越多，调和的成本越高。
▍六条已经过时的常识
博客给了六组「过去的常识」与「现在的做法」，几乎每一条都在推翻过去两年的最佳实践。
从给规则，到给判断　以前写「默认不写注释，最多一行」。现在写「写读起来像周围代码的代码」。前者在复杂代码上会出错，后者能自己看上下文。
从给例子，到设计接口　例子会把模型的探索空间框死。不如把参数设计好——Todo 工具只把状态定义成三个枚举值，用法就自明了。
从全部前置，到渐进披露　代码审查和验证流程被拆成独立技能，需要时才调用。工具也一样，有些改成延迟加载。
从重复强调，到简短说明　老模型更听结尾的话，所以同一件事要写两遍。新模型不需要。
从手写记忆，到自动记忆　以前让用户按 # 键往文件里存，现在模型自己判断什么值得记。
从简单规格，到丰富参考　HTML 原型、测试套件、甚至另一个代码库里的函数都能当参考。博客特别提到：「以代码形式给出的信息」比文字描述和截图效果更好。
▍落到实操
他们的建议是反「知识库」直觉的：CLAUDE.md 要保持轻，多写这个仓库特有的坑，不要写看一眼目录就知道的东西。
技能要写成「找信息的地图」而不是「操作手册」，长了就拆文件。
对做 agent 的人来说，这篇的价值不在具体条目，而在一句判断：当模型变强，你的提示词该做减法，而不是加法。如果你还在写两千字的系统提示去微操模型，很可能是在跟它较劲。
