# 每日公众号任务（automation prompt 原文）

> 下面两段分别用于 **09:45** 主任务与 13:00 兜底。
> （定 09:45 是因为「每日 AI 选题雷达」也在 9:00 跑，今天实测跑到 9:23，要留出余量。）整段粘进 automation 的 prompt。
> 脚本在 `scripts/`，规范在 `组件库.md` / `排版规范.md`。

---

## 09:45 主任务

今天只做两件事：**把库存补到 3 篇**、**发 1 篇**。绝不发第 2 篇。

### 第 0 步 盘点

```bash
python scripts/gzh_queue.py list --json
```

读 `stock` / `wip` / `todo` / `published_today`。
若 `.cache/STOP_AUTO` 存在 → 回一句「已急停」就结束。

### 第 1 步 补稿（`todo > 0` 才做，最多 2 篇）

每篇都要完整走完再开下一篇：

1. `python scripts/gzh_prep.py`
   - `exit 2` → 今日无 ★3 选题：**停止补稿**，记「库存不足」，跳到第 2 步
   - `exit 3` / `10` → 直接结束
2. 读 `<out_dir>/source.md` 与 `briefing.json`（**先读原文再写**）
3. 照 `组件库.md` 写 `<out_dir>/body.html`（只许 section/span/strong/br/img）
4. 填 `manifest.json` 的 `title`（≤64 字）与 `summary`（60–120 字）
5. 自检：
   ```bash
   python scripts/gzh_lint.py --manifest <out_dir>/manifest.json --form <form>
   python scripts/gzh_draft.py --manifest <out_dir>/manifest.json --check-only
   ```
   最多重写 2 次；第 3 次仍不过 → `python scripts/gzh_queue.py mark --dir <out_dir> --state dropped --note "lint_fail"`
6. 存草稿：
   ```bash
   python scripts/gzh_auto.py --manifest <out_dir>/manifest.json --daily-cap 3 --publish none
   ```
   - `exit 0` → 成功（状态自动转 drafted）
   - `exit 4` → 今日存稿配额满：停止补稿
   - `exit 5` → 登录失效：停止全部任务，汇报重扫命令
   - `exit 6` / `9` → `mark --state dropped`，继续下一篇（**不要重试同一篇**）
   - `exit 7` → 这篇已发表过，跳过

### 第 2 步 发 1 篇（无论第 1 步成败都做）

```bash
python scripts/gzh_publish.py --from-queue --mode qr-wait --wait-scan 240 --headed
```

- **`--headed` 必须有**：二维码要出现在可见窗口里，人才扫得到。
- `exit 0` + `published=true` → 已发表（记下标题与 `publish_appmsgid`）
- `exit 8` → 扫码超时：**不要重复点**。码已过期，13:00 会再出一次
- `exit 4` → 今天已发过（正常）。**不要换一篇再发**
- `exit 7` → 那篇已不在草稿箱（脚本已标 dropped）：最多再跑一次本命令
- `exit 5` → 登录失效，汇报重扫命令后结束
- `exit 2` → 队列无可发：汇报「库存为空」+ 第 1 步结果

### 第 3 步 汇报

读 `运行台账/notice/<今天>.md`，把「结论 / 库存 / 需要人做的事」原样转述，
并给出二维码截图的绝对路径。**不要自行编造发表结果。**

## 13:00 兜底

只做一件事：补发一次。不写稿、不改稿。

1. `python scripts/gzh_queue.py list --json` —— `stock` 为 0 就结束
2. `python scripts/gzh_publish.py --from-queue --mode qr-wait --wait-scan 240 --headed`
3. 读 `运行台账/notice/<今天>.md` 汇报。`exit 4` = 今天已发（正常结束，不必当成失败）

---

## 硬红线

- **一天只能发 1 篇**。平台群发通知配额是 1 次/天，脚本也强制。
- **每篇发表都要扫一次码，这是平台硬限制**。不要试图「扫一次连发多篇」——已实测否证。
- 不编造事实与数字；不搬未授权的原创文章；不为凑字数注水。
- 不绕过 `gzh_lint` / `--check-only` 直接存稿。
- 发不出去就说清楚停在哪一步、草稿 id 是多少，不要粉饰。
